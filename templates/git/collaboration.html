Real-World Scenario: Parallel Multi-Developer Workflow

In collaborative software engineering, multiple teammates work simultaneously on independent features. Rather than committing straight to main, each developer forks or branches from main, commits changes incrementally, and submits a Pull Request (PR) for peer review.

Developer 1: Student Management

Feature Branch A

Implements models, routes, and views for student CRUD records:

# 1. Clone repository git clone https://github.com/Itzx-kush/Student-information-management-system.git # 2. Create and switch to feature branch git switch -c feature-student-management # 3. Stage and commit student CRUD files git add . git commit -m "Implement student management CRUD" # 4. Push feature branch to GitHub git push -u origin feature-student-management

Developer 2: Course Registration

Feature Branch B

Implements course catalogs, seat capacity logic, and registration:

# 1. Clone repository git clone https://github.com/Itzx-kush/Student-information-management-system.git # 2. Create and switch to feature branch git switch -c feature-course-registration # 3. Stage and commit course catalog files git add . git commit -m "Implement course registration system" # 4. Push feature branch to GitHub git push -u origin feature-course-registration

Integration & Pull Request Workflow on Main

Production Integration

The release lead synchronizes main, tests peer pull requests, merges approved contributions, and pushes the consolidated application:

# Ensure local main is up to date with remote git switch main git pull origin main # Integrate Developer 1's work git merge feature-student-management # Integrate Developer 2's work git merge feature-course-registration # Push integrated application to GitHub main git push origin main

Understanding & Resolving Merge Conflicts

What is a Merge Conflict? A merge conflict occurs when two branches have modified the exact same lines of code in a file differently, or one branch deleted a file while another modified it. Because Git cannot deduce author intent automatically, it pauses the merge and places conflict markers directly inside the affected files.

1. Git Conflict Markers in Source Code

<<<<<<< HEAD (Current branch / main) DATABASE_NAME = "student_management.db" ======= DATABASE_NAME = "student_records_v2.db" >>>>>>> feature-course-registration

2. Three-Step Resolution Procedure

  1. Edit the file: Open the file, choose the correct consolidated code, and remove the marker lines (<<<<<<<, =======, >>>>>>>).
  2. Stage the resolved file: Run git add <filename> to notify Git the conflict is solved.
  3. Complete the merge commit: Run git commit -m "Resolve merge conflict between main and feature".
